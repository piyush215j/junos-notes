📋 Client Audit Scenario: Core Link Telemetry & Health Audit

Client Organization: Apex Global Enterprise Core Backbone

Device Under Audit: Core Router Router 1 (Juniper MX-204 Universal Routing Platform)

Mission Background: Network operations has received alerts regarding packet fragmentation and intermittent link instability between Router 1 and the downstream distribution switches. Your task is to perform an exhaustive, non-intrusive operational inspection of physical link parameters (MAC addresses, L2/L3 MTUs, carrier stability, traffic rates, error counters) using detailed command outputs and advanced CLI pipe filtering techniques.

Core Troubleshooting Objectives:

  1. Audit Hardware & Current MACs: Verify burned-in hardware MAC addresses versus configured current MAC addresses.
  2. Detect MTU Mismatches: Pinpoint physical frame MTUs versus logical IP family MTUs across all active ports.
  3. Analyze Error Counters & Flaps: Identify CRC errors, framing errors, carrier transitions, and last-flap timestamps.
  4. Master CLI Output Stream Modifiers: Use match, except, count, find, and multi-stage pipe chaining to extract precise telemetry in seconds.
⚙️ Core Concept: The 5-Level Junos Interface Verbosity Ladder

Junos OS provides five standardized verbosity levels for operational interface inspection:

Level / Command Output Density Primary Information Displayed Best Used For
show interfaces terse 1 line per interface / unit Interface name, Admin status, Link status, Protocol family, IP address High-speed inventory & quick status checks
show interfaces brief Compact block (~4-6 lines) Encapsulation, Speed, Duplex, Link-mode, Addresses Quick physical layer verification
show interfaces <name> (Standard) Moderate block (~25-35 lines) Physical L1/L2 properties, Hardware/Current MAC, L2 MTU, L3 Units, Statistics Standard troubleshooting & interface verification
show interfaces <name> detail Detailed (~80-120 lines) Complete bit-rate statistics, CoS queue counters, L3 family MTUs, protocol flags Deep-dive performance & MTU investigation
show interfaces <name> extensive Exhaustive (150+ lines) Driver-level ASIC counters, PHY registers, MAC packet size distributions Hardware defect & physical carrier failure analysis

🔍 Key Field Analysis: Physical Layer Properties
  • Enabled, Physical link is Up: Administrative state is enabled; physical carrier is active.
  • Link-level type: Ethernet, MTU: 1800: Layer 2 physical maximum frame size is 1800 bytes (custom jumbo frame).
  • Current vs Hardware address: Both show 00:05:86:71:a1:01. The hardware address is the burned-in vendor MAC; current address is the active operational MAC (which can be overridden via mac configuration).
  • Last flapped: Indicates interface stability (no link flaps in nearly 3 days).

Part 6: Special Interfaces Audit (fxp0, lo0, irb, .16386)

Examine internal, management, and virtual interfaces found on Junos routers.

Step 6.1: Special Junos Interface Roles

Special Interfaces
Interface Type Default Name Primary Function & Characteristics
Out-of-Band Management fxp0 / em0 / me0 Dedicated physical Ethernet port on the Routing Engine. Completely isolated from the forwarding plane (transit traffic cannot enter/exit).
Loopback Interface lo0.0 Virtual, always-up software interface used for router ID, BGP peering, and applying Routing Engine firewall filters.
Integrated Routing & Bridging irb / vlan Layer 3 gateway interface on Juniper switches and routers terminating bridged VLAN broadcast domains.
Internal / System Units .16386 / .32767 Auto-generated internal logical units used by Junos daemons for control-plane routing protocol operations. Never deleted.

Part 8: JNCIA-Junos Interface Diagnostics & Filter Cheat Sheet

Command / Recipe Modifier Action Primary Use Case
show interfaces <name> Standard verbosity Displays MAC addresses, L2 MTU, speed, carrier states, and L3 units.
show interfaces <name> detail Detailed verbosity Shows bit rates, error counters, and address family MTUs.
show interfaces | match <regex> Substring / Regex match Filters live output stream to lines matching query.
show interfaces terse | except <regex> Inverse match Hides all lines matching query to isolate remaining ports.
show interfaces | match ... | count Chained line counter Returns instant integer count of matching lines.
show interfaces | find <term> Output jump Jumps output display directly to the first matching section.
