Binary & Bits
§1
What Is Binary?
  • Computers communicate using physical binary signals: high/low electrical impulses, on/off light pulses, north/south magnetic polarities.
  • Each individual 1 or 0 in these signals is called a bit.
  • The counting system they belong to is called binary — the word means "composed of two things."
  • A binary signal has no inherent meaning by itself. The receiving hardware interprets it based on context (pixel color, file data, network packet, keyboard input, etc.).
From Physical Signal to IP Address

Physical binary signals encode as bits, group into bytes, then assemble into addresses of fixed bit-widths. IPv6 at 128 bits is 296 times larger in address space than IPv4 at 32 bits.

  • 8 columns with all bits on: 11111111

  • More bits = exponentially more unique values encodable.

Hexadecimal
§2
Why Hexadecimal?
  • Humans struggle with long binary strings. We convert binary to more readable formats.
  • Decimal works but is inconsistent — the same 8-bit byte can be 1, 2, or 3 decimal characters wide (e.g., 5, 99, 255).
  • Hexadecimal (hex) represents any 8-bit byte in exactly two characters — perfectly consistent and compact.
  • This makes hex the preferred format for computing. It is used in: IPv6 addresses, MAC addresses, memory locations, color values, error codes.

Why Hexadecimal is Essential for IPv6:

Decimal width varies from 1 to 3 characters per byte, making 16-byte IPv6 addresses irregular and messy. In Hex, 1 byte is ALWAYS exactly 2 hex characters (and 1 nibble = 1 hex char). This guarantees that every 128-bit IPv6 address is consistently structured as 32 hex characters grouped into 8 clean 16-bit blocks (hexets).

The Hex Counting System

Hex uses 16 symbols (0–9 then A–F), versus decimal's 10 (0–9) and binary's 2 (0–1):

Why IPv6?
§3
IPv4 Address Exhaustion
  • IPv4 provides ~4.3 billion theoretical addresses.
  • Usable public addresses: ~3 billion (private ranges, reserved blocks, broadcast reduce this).
  • World population > 8 billion; most people own multiple network devices.
  • The internet has effectively exhausted the IPv4 address pool.
IPv6 Adoption
  • IPv6 was designed decades ago but gained urgency as IPv4 exhausted.
  • Late 2023: 45% of all Google incoming traffic came from IPv6 addresses.
  • Adoption continues to grow year over year.
  • Rate of adoption varies by country and industry.
  • IPv6 knowledge is increasingly required for real-world networking roles.

IPv6 Address Format
§4
Structure & Terminology
  • An IPv6 address is 128 bits long.
  • Written as 32 hexadecimal characters.
  • Colons group every 4 hex digits together — the same role that dots play in IPv4.
  • This creates 8 groups of 4 hex digits.
  • Each 4-hex-digit group is called a hexet (16 bits each).
📐

IPv6 Abbreviation Rules
§5

Two abbreviation rules let you shorten an IPv6 address. They are applied in order. You do not have to write all 32 hex characters.

Full Address
Step 1 — Leading Zeros
Step 2 — Double Colon
Final Result

Starting long-form address (32 hex chars, 8 hexets):

2001:0DB8:0000:0000:0000:0000:0000:0001
  • Contains leading zeros inside hexets (e.g., 0DB8)
  • Contains multiple consecutive all-zero hexets (0000:0000:0000:0000:0000)
  • Both can be shortened using the two rules below
1️⃣
Rule: Remove leading zeros from within each hexet. You may suppress zeros from the LEFT of a hexet only. Trailing zeros are kept. If a hexet is all zeros, it becomes a single 0.

Before:

2001:0DB8:0000:0000:0000:0000:0000:0001

After removing leading zeros from each hexet:

2001:DB8:0:0:0:0:0:1
  • 0DB8 → DB8 (one leading zero removed)
  • 0000 → 0 (three leading zeros removed; one zero remains)
  • 0001 → 1
  • 2001 → 2001 (no leading zeros — unchanged)
2️⃣
Rule: Replace the longest consecutive run of all-zero hexets with :: (double colon). When reading an address, wherever you see ::, expand it to as many all-zero hexets as needed to bring the total back to 8 hexets.

After Step 1:

2001:DB8:0:0:0:0:0:1

Replace the five consecutive zero-hexets with :::

2001:DB8::1
  • Five hexets (0:0:0:0:0) collapsed to ::
  • To expand: this address has 3 explicit hexets (2001, DB8, 1); subtract 3 from 8 = 5 zero-hexets must fill the :: position

Full original:

2001:0DB8:0000:0000:0000:0000:0000:0001

Shortened form:

2001:db8::1
✅
Both forms are the same address. The short form 2001:db8::1 is how you will see this address written in all documentation, training material, and Juniper examples.
Strict Rules for Step 2 (Double Colon ::)
⚠️  Rule 1 — Always shorten the longest consecutive zero run ▼

When an address has multiple separate zero runs, you must use :: on the longer one:

Example
Address:  2001:0000:0000:AB00:0000:0000:0000:0001
          Hexets 2-3: run of 2 zeros
          Hexets 5-7: run of 3 zeros   ← longer

Correct:  2001:0:0:AB00::1        (:: on the 3-hexet run)
Incorrect: 2001::AB00:0:0:0:1      (:: on the shorter run — wrong)
⚠️  Rule 2 — :: may appear only once ▼

Using :: twice in one address creates ambiguity — you cannot determine how many zeros each :: represents, so it is illegal:

Example
Address:  2001:0000:0000:AB00:0000:0000:0000:0001

Illegal:  2001::AB00::1
          ↑                ↑ — ambiguous, cannot expand
⚠️  Rule 3 — Never use :: to replace a single all-zero hexet ▼

A lone all-zero hexet is already shortened to 0 by Step 1. Step 2's :: requires two or more consecutive all-zero hexets:

Example
Address:  2001:db8:1:2:3:4:0000:6

Correct:  2001:db8:1:2:3:4:0:6     (Step 1 only)
Incorrect: 2001:db8:1:2:3:4::6     (cannot use :: for single hexet)
:: Rules — Valid vs Invalid at a glance
✓ Valid
2001:0:0:AB00::1
:: replaces the longer run (3 zeros, hexets 5–7)
✗ Invalid
2001::AB00:0:0:0:1
:: replaces the shorter run (only 2 zeros) — must use longest run
✓ Valid
2001:db8:1:2:3:4:0:6
Single zero hexet → Step 1 only. :: cannot be used for a single hexet
✗ Invalid
2001::AB00::1
:: appears twice — ambiguous, cannot determine which group it expands
💡
Expanding :: back to full form: Count the visible hexets. Subtract from 8. Insert that many 0000 hexets where the :: appears. Example: 2001:db8::1 → 3 visible hexets → 8 − 3 = 5 zero hexets fill the ::.

IPv6 Subnetting
§6

Although 128 possible prefix lengths exist in IPv6, in practice you only need to know two. IPv6 subnetting is significantly simpler than IPv4.

/64 and /128 — Network vs Host bit allocation per hexet

Blue hexets 1–4 are the /64 network prefix. Green hexets 5–8 are the 64-bit host field. In /128, all hexets are fixed (orange) — a single unique device is identified, no hosts can vary.

/64 — Standard LAN Subnet
  • The standard prefix for any LAN — almost universally used.
  • First 64 bits (first 4 hexets) = network portion.
  • Last 64 bits (last 4 hexets) = host portion.
  • The host portion (264 addresses) is so large that devices can auto-generate their own unique host address with near-zero collision risk.
  • Eliminates all IPv4 subnet-sizing decisions (/25, /24, /23, /22, etc.).
Network First 64 bits · Hexets 1–4
Host Last 64 bits · Hexets 5–8
/64 Structure
2001:db8:1:1:xxxx:xxxx:xxxx:xxxx/64
└─ network (4 hexets) ─┘ └──── host (4 hexets) ────┘
/128 — Single Host
  • All 128 bits are the network portion — zero host bits.
  • Identifies exactly one single device; no hosts can vary.
  • Used for loopback addresses and host routes.
  • Logical: IPv6 = 128 bits, so /128 means all 128 bits are fixed.
Single Host — All 128 bits fixed No host portion exists
/128 Structure
2001:db8::1/128
└─── entire 128 bits fixed — one device only ───┘
✅
Almost all IPv6 LANs use /64. This is effectively the global standard. The 264 host addresses per LAN means you will never run out of addresses on a subnet. The IPv4 questions of "how many hosts do I have now?" and "how many will I have in the future?" disappear entirely.
Prefix Use Case Network Bits Host Bits Hosts Possible

Link-Local Addresses
§7
⚡
Auto-assigned on IPv6 enable: The moment IPv6 is enabled on any interface, the interface automatically assigns itself a link-local address. No manual configuration is required.
Key Properties
  • Identifying prefix: All link-local addresses begin with FE80 (range: FE80::/10).
  • Scope: Valid only on the local link (directly connected segment). Has no meaning beyond the interface it is assigned to.
  • Never advertised: Link-local addresses are never advertised by routing protocols or forwarded beyond the local link. Even if they were, they would be meaningless.
  • Auto-generated: Created automatically by the device. You will rarely need to know or manually configure the specific link-local address.

🔑 Essential Exam Rules for Link-Local Addresses (FE80::/10):
1. Local Scope Only:

A link-local address is valid only on the directly connected physical wire (link). It does not exist beyond that interface.

2. Non-Routable by Design:

Routers will never route or forward link-local packets across interfaces. A cross-link ping is always dropped at the ingress interface.

3. Interface Re-use:

Because scopes are independent, different interfaces (even on the same router) can safely use the exact same link-local address without conflict!

Uses of Link-Local Addresses
  • Neighbor Discovery Protocol (NDP) — IPv6 replacement for ARP; discovers other devices on the same link using link-local addresses.
  • Router Discovery — Routers advertise themselves using their link-local addresses.
  • Any communication directly between devices on the same link.
Ping Behavior Test
  • If Router A pings a link-local address that belongs to Router B's interface connecting B–C:
  • The ping arrives at Router B but is dropped — the address has no meaning on the A–B link.
  • This is by design: link-local scope is intentional and enforced.
🔑
Two things you know when you see an address starting with FE80:
  • It was automatically generated by the device — not manually configured.
  • It is only meaningful on the specific interface it is assigned to — it will never be routed.
